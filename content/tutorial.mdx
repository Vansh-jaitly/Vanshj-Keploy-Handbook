## TL;DR

<Callout type="info" title="In one minute">

I ran Keploy's Echo + Postgres quickstart on Windows through WSL2. Keploy sat in front of a small Go URL shortener, watched my API calls, and saved each one as a test. It also saved every Postgres reply as a mock. Then I replayed the tests, stopped the database, and replayed them again.

**What you'll have at the end:**

- 8 test cases recorded from 7 curl calls and one stray browser visit
- a suite that passes 8/8 with Postgres switched off
- a regression caught on purpose: a one-word change from 308 to 307 failed exactly the two redirect tests

</Callout>

## Why Keploy

Testing an API that talks to a database usually means one of two chores: keep a real database running for every test run, or hand-write mocks and hope they still match what the database says. Both drift, and both cost time.

Keploy records real traffic instead, and turns each request into a test and each database exchange into a mock. My pitch to a Go developer:

> Keploy turns the API calls you already make into tests and records your database's answers as mocks, without touching your code. Run it once while you click around, and you get a regression suite that runs without Postgres.


## How it works

Keploy starts your app and sits on both sides of it: in front of the app for incoming requests, and in front of Postgres, through its proxy, for database traffic. So it sees both halves of every request.

## Meet the sample app

A URL shortener built with Echo and Postgres. I read the code before running anything, so I'd know what correct output looks like.

<EndpointTable

Two details matter later. Every handler pings the database first, and the app creates its own `url_map` table at startup. And only the `ts` field changes between requests (it's `time.Now().UnixNano()`).

<Callout type="tip" title="The short code is deterministic">

It's the SHA-256 of the URL, base58-encoded, first 8 characters. `https://github.com` always becomes `4KepjkTT`.

</Callout>

<Callout type="info" title="308, not 302">

`GET` redirects with `http.StatusPermanentRedirect`: **308 Permanent Redirect**, not 302. Remember it. I break it on purpose later.

</Callout>

I used Go 1.26, Docker 29.8.1 (Docker Desktop), git and curl. Pick your OS:

<Tabs labels={["Windows (WSL2)", "Linux", "macOS"]} label="Operating system">

### A test case is plain YAML

My first test, trimmed. I wrote none of it, including the highlighted noise rules:

```yaml title="keploy/test-set-1/tests/post-url-1.yaml (trimmed)" {18-20}
# Generated by Keploy (3.8.58)
version: api.keploy.io/v1beta1
kind: Http
name: post-url-1
spec:
  req:
    method: POST
    url: http://localhost:8082/url
    header:
      Content-Type: application/json
      User-Agent: curl/8.18.0
    body: '{"url": "https://github.com"}'
  resp:
    status_code: 200
    body: |
      {"ts":1791011549050753557,"url":"http://localhost:8082/4KepjkTT"}
  assertions:
    noise:
      body.ts: []
      header.Date: []
  app_port: 8082
curl: |-
  curl --request POST \
    --url http://localhost:8082/url \
    --header 'Content-Type: application/json' \
    --data "{\"url\": \"https://github.com\"}"
```

- **A test is the request plus the response.** Readable, editable YAML.
- **`noise` lists fields to skip when comparing.** `body.ts` and `header.Date` change every run, which is why replay passes even though `ts` differs.
- **Each test carries a ready-to-run `curl` command** for reproducing it by hand.
- The redirect test `get-4kepjktt-1` recorded `status_code: 308` and `Location: https://github.com`, with only `header.Date` as noise.

### Which mocks belong to which test

`mappings.yaml` links every test to the database replies it needs:

```yaml title="keploy/test-set-1/mappings.yaml (excerpt)"
kind: TestMocksMapping
test_set_id: test-set-1
tests:
    - id: post-url-1
      mock_entries:
        - name: mock-4
          kind: PostgresV3
        - name: mock-5
          kind: PostgresV3
    - id: get-4kepjktt-1
      mock_entries:
        - name: mock-7
          kind: PostgresV3
```

The full mapping, in short:

| Test | Mocks | Why |
|---|---|---|
| `post-url-1`, `post-url-2` | 2 each | SELECT, then INSERT or UPDATE |
| `put-4kepjktt-1` | 2 | SELECT, then UPDATE |
| both GETs, `get-doesnotexist-1`, `delete-4kepjktt-1` | 1 each | a single query |
| `post-url-3` | 0 | fails validation before any SQL |
| `startup` section | `mock-2` | needed before any request |

The per-test mocks add up to 10.

### The recorded Postgres conversation

`mocks.yaml` holds 22 entries. Here are the first three, trimmed:

```yaml title="keploy/test-set-1/mocks.yaml (first 3 of 22, trimmed)"
kind: PostgresV3
name: mock-0
spec:
    metadata:
        lifetime: connection
        type: config
    postgresV3:
        type: session
        session:
            protocolVersion: "3.0"
            serverVersion: 10.5 (Debian 10.5-2.pgdg90+1)
            observedAuthMode: md5
---
kind: PostgresV3
name: mock-1
spec:
    postgresV3:
        type: query
        query:
            class: VALIDATION
            sqlNormalized: ;
---
kind: PostgresV3
name: mock-2
spec:
    metadata:
        class: DDL
    postgresV3:
        type: query
        query:
            sqlNormalized: "CREATE TABLE IF NOT EXISTS url_map (id VARCHAR(255) PRIMARY KEY, redirect_url VARCHAR(255) NOT NULL, created_at TIMESTAMP NOT NULL, updated_at TIMESTAMP NOT NULL);"
            response:
                commandComplete: CREATE TABLE
```

- `mock-0` is the **connection handshake**. Without it the app can't even connect during replay, as I found out the hard way.
- `mock-1` is the driver's validation ping, `;`.
- `mock-2` is the startup `CREATE TABLE`, with Postgres's reply.

The traffic is stored as structure (query class, normalized SQL, response), not raw bytes. And the math adds up: auto-replay reported **10** per-test mocks and **12** connection and config mocks. 10 + 12 = 22, which matches `grep -c "kind:" mocks.yaml`.


## Troubleshooting

Every problem I hit, in the order I hit them. Paste part of an error into the filter to jump to it.

<Troubleshooting>
<Problem title="sudo is disabled on this machine" error="sudo is disabled on this machine">

**Cause:** I ran the command in PowerShell, which uses Windows' own `sudo`.

**Fix:** Don't enable Windows sudo. Open the Ubuntu terminal; the prompt should look like `user@host:~$`. A PowerShell prompt showing `\\wsl.localhost\Ubuntu\...` is still PowerShell.

</Problem>
<Problem title="Pasted a placeholder literally" error={"The '<' operator is reserved for future use\nbash: syntax error near unexpected token 'newline'"}>

**Cause:** I pasted placeholder text like `<postgres-service-name>` as-is.

**Fix:** Replace placeholders, angle brackets included, with real values. Here that was `postgres`.

</Problem>
<Problem title="Permission denied on the Docker socket" error="permission denied while trying to connect to the docker API at unix:///var/run/docker.sock">

**Cause:** My Ubuntu user wasn't allowed to use Docker.

**Fix:** In Docker Desktop, turn on Settings → Resources → WSL Integration → Ubuntu. Then run `sudo usermod -aG docker $USER`, run `wsl --shutdown` in PowerShell, reopen Ubuntu, and check `docker ps`.

</Problem>
<Problem title="go build can't find C headers" error="fatal error: stdint.h: No such file or directory">

The same error showed up for `pthread.h` and `stdio.h`.

**Cause:** A fresh Ubuntu has gcc but no C library headers, and Go's cgo needs them.

**Fix:** `sudo apt install -y build-essential`

</Problem>
<Problem title="sudo -E PATH=$PATH breaks on WSL" error={"sudo: preserving the entire environment is not supported, '-E' is ignored\nsudo: 'Files/Common': command not found"}>

**Cause:** WSL appends the Windows `PATH`, which contains spaces (for example `Program Files`). The unquoted `PATH=$PATH` splits at the space. This `sudo` also doesn't support `-E`.

**Fix:** Quote it: `sudo env "PATH=$PATH" keploy ...`. Or use `sudo $(which keploy) ...`.

</Problem>
<Problem title="First keploy test crashes on test-set-0" error={"failed to unmarshal a mock yaml doc of unknown type {\"type\": \"Postgres\"}\nmissing PostgresV3Session mock — cannot reply to StartupMessage"}>

The first error repeated 18 times, then the app exited with `EOF`.

**Cause:** The cloned repo ships an old `keploy/test-set-0` in a mock format 3.8.58 can't read. Keploy replays it first, and the app can't connect.

**Fix:** Replay only your own set with `--test-sets test-set-1`.

</Problem>
<Problem title="A browser sign-in opens mid-run" error="Session expired. Re-authenticating via browser...">

**Cause:** The Keploy CLI session login, triggered during auto-replay after recording.

**Fix:** Sign in once and return to the terminal; the replay continues. You don't need Keploy MCP or an API key for local record and replay.

</Problem>
</Troubleshooting>

## Docs gaps I'd fix

The quickstart got me there. These are the changes I'd suggest:

1. **Host line:** it says line 41 and `postgres`. My clone had line 47, shipped as `postgresDb`; the native route needs `localhost`.
2. **Windows/WSL:** a short note on which terminal to use, Docker's WSL integration and the `docker` group.
3. **C toolchain:** `go build` needs `build-essential` on a fresh Ubuntu.
4. **`sudo -E PATH=$PATH`:** breaks when the Windows `PATH` has spaces, and on `sudo` builds without `-E`. `sudo env "PATH=$PATH"` works.
5. **Bundled `test-set-0`:** it breaks replay on 3.8.58. Suggest `--test-sets`, or remove the old set.
6. **Login, auto-replay, uploads:** none are mentioned. A heads-up before the first run would help.
7. **How `ts` is ignored:** the docs say it "would automatically be ignored" but not how. Point to the `noise` block.
8. **`docker-compose`:** current Docker uses `docker compose`. Both worked for me.

## Honest notes

What I'd want to know before using this on a real project:

- **Account friction:** a browser login mid-run, not explained in the quickstart.
- **Data leaves the machine:** the Free edition uploaded mocks and a test report. Think first with real user data.
- **Loud logs:** DNS takeover notices, Java truststore messages for a Go app, matching diagnostics. Useful for debugging, noisy for a beginner.
- **Matching isn't always exact:** Keploy tolerated driver-level parameter type drift and said so. Worth remembering if a replayed response looks wrong.
- **Tests reflect recorded state:** great for isolation, but you only test the traffic you recorded.
- **`mocks.yaml` grows fast:** 22 entries for 8 requests, and Keploy's guidance is not to commit it to Git.
- **Every test set runs by default,** so a stale set can break a clean run.
- **Summary blocks aimed at AI agents** appear in the output; one claimed success after a crash.
- The `"error":"sync /dev/stderr: invalid argument"` line at exit comes from the app's logger, not Keploy. Harmless.
